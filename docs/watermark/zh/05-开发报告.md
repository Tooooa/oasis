```python
class WatermarkManager:
    def sample_behavior_watermark(self, probabilities, round_num, context_for_key):
        """差分水印采样"""
        # 1. 排序行为
        sorted_behaviors = sorted(probabilities.items(), 
                                 key=lambda x: x[1], reverse=True)
        
        # 2. 获取下一个bit
        bit = self.bit_stream[self.current_bit_index % len(self.bit_stream)]
        
        # 3. 差分重组
        selected = differential_based_recombination(
            sorted_behaviors, bit, self.delta, self.gamma
        )
        
        return selected
```

### 阶段 4: 验证逻辑改进 (11月9日晚)

**问题**: 初始验证逻辑存在问题

**发现**:
1. 概率分布太集中时（如 0.95, 0.05），无法有效嵌入
2. 验证逻辑未考虑"跳过嵌入"的情况
3. ECC 验证对不完整块报告错误

**改进**:
```python
# 新增: 检查概率分布是否适合嵌入
def can_embed_watermark(probabilities, threshold=0.1):
    """检查概率分布的多样性"""
    sorted_probs = sorted(probabilities.values(), reverse=True)
    if len(sorted_probs) >= 2:
        # 前两个概率差距太大，无法嵌入
        if sorted_probs[0] - sorted_probs[1] > threshold:
            return False
    return True
```

**结果**:
- ✅ 准确区分"有效嵌入"和"跳过嵌入"
- ✅ 统计更准确
- ✅ 部分块也能正确验证

**文档**: `docs/验证逻辑改进说明.md`

## 技术决策

### 1. 非侵入式集成

**决策**: 通过可选参数传递 `watermark_manager`

**理由**:
- ✅ 不修改 OASIS 核心
- ✅ 保持向后兼容
- ✅ 易于维护

**替代方案**:
- ❌ 直接修改 OASIS 核心 - 侵入性太强
- ❌ 独立的 Wrapper 类 - 复杂度高

---

### 2. 独立 Agent 水印

**决策**: 每个 Agent 自动创建独立的 `WatermarkManager`

**理由**:
- ✅ 每个 Agent 可独立追踪
- ✅ 日志文件独立，便于分析
- ✅ 支持大规模多 Agent 实验

**实现**:
```python
class SocialAgent:
    def __init__(self, agent_id, ..., watermark_manager=None):
        if watermark_manager is None:
            # 自动创建独立水印管理器
            self.watermark_manager = WatermarkManager(
                enabled=True,
                bit_stream=format(agent_id, '08b'),  # 嵌入 agent_id
                log_dir=f"./outputs/logs/watermark"
            )
```

---

### 3. ECC 选择: Parity

**决策**: 使用 Parity 而非 Hamming

**对比**:

| 方案 | Overhead | 纠错能力 | 复杂度 |
|------|----------|----------|--------|
| Parity | 1 bit | 检测 1 错误 | 低 |
| Hamming | 4 bits | 纠正 1 错误 | 中 |

**理由**:
- ✅ Parity 足够用于 Agent 行为场景
- ✅ Overhead 最小 (8 bit → 9 bit)
- ✅ 实现简单，调试容易

---

### 4. 日志格式: JSON Lines

**决策**: 使用 JSONL 格式记录水印日志

**格式**:
```json
{"round": 0, "behavior": "create_post", "prob_before": 0.45, "prob_after": 0.48, "bit": "1"}
{"round": 1, "behavior": "like_post", "prob_before": 0.32, "prob_after": 0.35, "bit": "1"}
```

**理由**:
- ✅ 易于解析和分析
- ✅ 支持流式写入
- ✅ 可读性好

## 遇到的挑战

### 挑战 1: 概率分布不适合嵌入

**问题**: 
```python
probabilities = {
    "create_post": 0.95,  # 太高
    "like_post": 0.05     # 太低
}
# 无法通过排序重组嵌入bit
```

**解决**:
```python
# 检测并跳过
if max_prob - second_max_prob > threshold:
    logger.warning("概率分布太集中，跳过嵌入")
    return max_behavior, targets, "", context
```

---

### 挑战 2: 导入路径错误

**问题**: 移动文件后，`sys.path` 设置不正确

**错误**:
```
ModuleNotFoundError: No module named 'oasis'
```

**解决**:
```python
# 原来: 回到 1 层父目录
sys.path.insert(0, str(Path(__file__).parent))

# 修复: 回到 3 层父目录
sys.path.insert(0, str(Path(__file__).parent.parent.parent))
```

---

### 挑战 3: 日志文件管理

**问题**: 日志分散在多个目录，难以管理

**解决**: 统一输出到 `outputs/logs/watermark/`

```
outputs/
└── logs/
    ├── oasis/          # OASIS 系统日志
    └── watermark/      # 水印日志 (唯一位置)
        └── 2025-11/
```
