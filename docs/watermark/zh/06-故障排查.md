## 安装问题

### 问题 1: ModuleNotFoundError: No module named 'oasis'

**症状**:
```
Traceback (most recent call last):
  File "custom_agent_run.py", line 5, in <module>
    from oasis.watermark import WatermarkManager
ModuleNotFoundError: No module named 'oasis'
```

**原因**: 
- Python 路径未正确设置
- 文件位置不在项目根目录下

**解决方案**:

**方法 1**: 检查 `sys.path` 设置

```python
import sys
from pathlib import Path

# 确保回到项目根目录（3层父目录）
project_root = Path(__file__).parent.parent.parent
sys.path.insert(0, str(project_root))

# 现在可以导入
from oasis.watermark import WatermarkManager
```

**方法 2**: 使用 pip 安装

```bash
# 在项目根目录运行
pip install -e .
```

**方法 3**: 添加到 PYTHONPATH

```bash
# Windows PowerShell
$env:PYTHONPATH = "D:\_Development\Agentguide\OASIS\oasis"

# Linux/Mac
export PYTHONPATH="/path/to/oasis"
```

### 问题 3: API Key 未找到

**症状**:
```
Error: API key not found. Please set OPENAI_API_KEY environment variable.
```

**原因**: 
- 未设置 API Key
- 环境变量名错误
- 配置文件路径不对

**诊断步骤**:

**Step 1**: 检查环境变量

```powershell
# Windows PowerShell
echo $env:OPENAI_API_KEY
echo $env:DEEPSEEK_API_KEY

# 应该显示你的 API Key，如果是空白则未设置
```

**Step 2**: 检查配置文件

```python
import json
from pathlib import Path

# 查找配置文件
config_paths = [
    "./config.json",
    "./examples_watermark/config.json",
    "./oasis/config.json"
]

for path in config_paths:
    if Path(path).exists():
        print(f"Found config: {path}")
        with open(path) as f:
            config = json.load(f)
            print(f"API Key: {config.get('model', {}).get('api_key', 'NOT FOUND')[:10]}...")
```

**解决方案**:

**方法 1**: 设置环境变量（推荐）

```powershell
# Windows PowerShell - 临时设置
$env:DEEPSEEK_API_KEY = "sk-your-actual-key-here"

# Windows PowerShell - 永久设置
[System.Environment]::SetEnvironmentVariable('DEEPSEEK_API_KEY', 'sk-your-actual-key-here', 'User')
```

**方法 2**: 使用配置文件

```bash
# 复制模板
cp config.json.template config.json

# 编辑并填入 API Key
notepad config.json
```

```json
{

  }
```

### 问题 7: 概率分布无法嵌入

**症状**:
```
WARNING: Probability distribution too concentrated, skipping embedding
Embedding rate: 20% (too low)
```

**原因**: 
- 行为概率分布太集中（如 0.95 vs 0.05）
- 无法通过排序重组嵌入 bit

**诊断**:

```python
# 检查概率分布
probabilities = {
    "create_post": 0.95,  # 太高
    "like_post": 0.05     # 太低
}

# 无法嵌入的条件
max_prob = max(probabilities.values())
second_max = sorted(probabilities.values(), reverse=True)[1]

if max_prob - second_max > 0.10:  # 差距太大
    print("❌ Cannot embed watermark")
```

**解决方案**:

**方法 1**: 调整 Agent 行为模型

```python
# 修改 prompt，增加行为多样性
prompt_template = """
You are a social media user with diverse interests.
Consider multiple possible actions:
1. Create a post (probability: ~30%)
2. Like a post (probability: ~30%)
3. Comment on a post (probability: ~25%)
4. Share a post (probability: ~15%)

Choose an action based on the current context.
"""
```

**方法 2**: 调整水印参数

```python
# 增大 gamma，使概率分布更平滑
watermark_mgr = WatermarkManager(
    enabled=True,
    bit_stream="11001101",
    delta=2.0,
    gamma=0.35  # 增大到 0.35（默认 0.25）
)
```

**方法 3**: 接受较低嵌入率

```python
# 嵌入率 50-70% 也是可接受的
# 只要有足够的嵌入 bits，仍能验证
```

**详细说明**: 参考 `docs/验证逻辑改进说明.md`

### 问题 8: LLM API 超时

**症状**:
```
openai.error.Timeout: Request timed out after 30s
```

**原因**: 
- 网络连接不稳定
- API 服务器负载高
- Timeout 设置太短

**解决方案**:

**方法 1**: 增加 Timeout

```python
from openai import OpenAI

client = OpenAI(
    api_key=api_key,
    timeout=60.0  # 增加到 60 秒
)
```

**方法 2**: 添加重试逻辑

```python
import time
from functools import wraps

def retry_on_timeout(max_retries=3, delay=2):
    """超时重试装饰器"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if "timeout" in str(e).lower() and attempt < max_retries - 1:
                        print(f"⚠️ Timeout, retrying ({attempt + 1}/{max_retries})...")
                        time.sleep(delay)
                    else:
                        raise
        return wrapper
    return decorator

@retry_on_timeout(max_retries=3)
def call_llm(prompt):
    return client.chat.completions.create(...)
```

**方法 3**: 使用更稳定的 API

```python
# 切换到 DeepSeek（通常更稳定）
model = ModelFactory.create(
    model_platform=ModelPlatformType.OPENAI,
    model_type="deepseek-chat",
    url="https://api.deepseek.com"
)
```

## 性能问题

### 问题 9: 运行速度太慢

**症状**:
- 10 个 Agent 运行 10 轮需要 30+ 分钟

**诊断**:

```python
import time

# 测量每个步骤的时间
start = time.time()

# Agent 行为生成
agent.perform_action()

elapsed = time.time() - start
print(f"Time per action: {elapsed:.2f}s")

# 如果 > 5s/action，说明有问题
```

**解决方案**:

**方法 1**: 启用并发执行

```python
import concurrent.futures

# 并发执行多个 Agent
with concurrent.futures.ThreadPoolExecutor(max_workers=10) as executor:
    futures = [executor.submit(agent.perform_action) for agent in agents]
    concurrent.futures.wait(futures)

# 速度提升 5-10x
```

**方法 2**: 减少 LLM 调用

```python
# 批量生成行为（如果支持）
actions = agent.perform_actions_batch(num_actions=10)
```

**方法 3**: 使用更快的模型

```python
# DeepSeek 通常比 GPT-4 快 2-3x
model = ModelFactory.create(
    model_type="deepseek-chat"
)
```

### 问题 10: 内存占用过高

**症状**:
- 内存使用 > 8GB
- 系统变慢或崩溃

**诊断**:

```python
import psutil

# 检查内存使用
process = psutil.Process()
memory_mb = process.memory_info().rss / 1024 / 1024
print(f"Memory usage: {memory_mb:.2f} MB")
```

**解决方案**:

**方法 1**: 分批运行

```python
# 不要一次创建 100 个 Agent
# 分批运行
batch_size = 10
for batch_idx in range(0, num_agents, batch_size):
    batch_agents = agents[batch_idx:batch_idx + batch_size]
    
    # 运行该批次
    for agent in batch_agents:
        agent.perform_action()
    
    # 清理内存
    del batch_agents
    import gc
    gc.collect()
```

**方法 2**: 禁用日志缓存

```python
# 实时写入日志，不要缓存
watermark_mgr = WatermarkManager(
    enabled=True,
    bit_stream="11001101",
    log_buffer_size=0  # 不缓存
)
```

**方法 3**: 使用数据库存储而非内存

```python
# 将历史记录存到数据库，而非内存
agent.use_database_history = True
```

## 验证问题

### 问题 11: 验证失败但日志正常

**症状**:
```
Original payload: 11001101
Decoded payload:  10001101
❌ WATERMARK VERIFICATION FAILED
```

**原因**: 
- 嵌入率太低（< 50%）
- ECC 解码错误
- Payload 不匹配

**诊断步骤**:

**Step 1**: 检查嵌入率

```python
import json

log_file = "outputs/logs/watermark/2025-11/watermark-agent0-*.log"

total = 0
embedded = 0

with open(log_file) as f:
    for line in f:
        entry = json.loads(line)
        total += 1
        if entry.get("embedded", False):
            embedded += 1

embedding_rate = embedded / total * 100
print(f"Embedding rate: {embedding_rate:.1f}%")

# 至少需要 50% 才能验证
if embedding_rate < 50:
    print("❌ Embedding rate too low")
```

**Step 2**: 检查 bit 匹配

```python
# 提取嵌入的 bits
embedded_bits = []
with open(log_file) as f:
    for line in f:
        entry = json.loads(line)
        if entry.get("embedded", False):
            embedded_bits.append(entry["bit"])

# 对比原始 payload
original_payload = "11001101"
bit_stream = "".join(embedded_bits)

print(f"Original: {original_payload}")
print(f"Embedded: {bit_stream[:len(original_payload)]}")

# 逐 bit 对比
for i, (orig, emb) in enumerate(zip(original_payload, bit_stream)):
    if orig != emb:
        print(f"❌ Mismatch at bit {i}: expected {orig}, got {emb}")
```

**解决方案**:

**方法 1**: 增加模拟轮数

```python
# 更多轮次 = 更多嵌入机会
num_rounds = 20  # 增加到 20 轮
```

**方法 2**: 调整水印参数

```python
# 使用更激进的参数
watermark_mgr = WatermarkManager(
    enabled=True,
    bit_stream="11001101",
    delta=2.5,   # 增大
    gamma=0.30   # 增大
)
```

**方法 3**: 使用更短的 Payload

```python
# 8 bit payload 需要至少 9 次嵌入（含 parity）
# 如果嵌入率只有 50%，需要 18 轮
# 或者使用更短的 payload
short_payload = "1100"  # 4 bits，只需 5 次嵌入
```

### 问题 12: Parity Check 失败

**症状**:
```
Parity check: ❌ Failed
```

**原因**: 
- 嵌入过程中出现错误
- 日志记录不准确
- ECC 解码错误

**诊断**:

```python
from oasis.watermark.coding_utils import parity_encode, parity_decode

# 测试 ECC
original = "11001101"
encoded = parity_encode(original)
print(f"Encoded: {encoded}")  # 应该是 110011010

# 解码
decoded, valid = parity_decode(encoded)
print(f"Decoded: {decoded}")
print(f"Valid: {valid}")

# 测试错误修正
corrupted = "110011011"  # 最后一位翻转
decoded, valid = parity_decode(corrupted)
print(f"Decoded (corrupted): {decoded}")
print(f"Valid (corrupted): {valid}")  # 应该是 False
```

**解决方案**:

**方法 1**: 检查日志完整性

```python
# 确保日志文件完整写入
watermark_mgr.flush_logs()  # 手动刷新

# 验证日志文件大小
import os
log_size = os.path.getsize(log_file)
if log_size < 100:  # 太小
    print("❌ Log file incomplete")
```

**方法 2**: 使用更强的 ECC

```python
# 如果数据质量差，考虑使用 Hamming
# （需要先实现 Hamming ECC）
watermark_mgr = WatermarkManager(
    enabled=True,
    bit_stream="11001101",
    ecc_type="hamming"  # 纠错能力更强
)
```

### Issue 1: Windows 路径分隔符

**描述**: Windows 使用 `\`，Linux/Mac 使用 `/`

**影响**: 路径字符串可能在不同系统上失败

**解决**: 始终使用 `pathlib.Path`

```python
from pathlib import Path

# ✅ 跨平台
log_dir = Path("outputs") / "logs" / "watermark"

# ❌ 仅限 Windows
log_dir = "outputs\\logs\\watermark"
```

### Issue 2: JSON 日志格式不统一

**描述**: 早期版本的日志格式可能不同

**影响**: 验证脚本可能无法解析旧日志

**解决**: 迁移旧日志格式

```python
import json

# 读取旧格式
with open("old_log.log") as f:
    old_entries = [json.loads(line) for line in f]

# 转换为新格式
new_entries = []
for entry in old_entries:
    new_entry = {
        "round": entry.get("round_num", 0),
        "behavior": entry.get("action", "unknown"),
        "prob_before": entry.get("prob", 0.0),
        "prob_after": entry.get("prob_watermarked", 0.0),
        "bit": entry.get("bit_embedded", "0"),
        "embedded": entry.get("is_embedded", False)
    }
    new_entries.append(new_entry)

# 写入新格式
with open("new_log.log", 'w') as f:
    for entry in new_entries:
        f.write(json.dumps(entry) + "\n")
```

### Issue 3: DeepSeek API 限流

**描述**: DeepSeek 有每分钟请求限制

**影响**: 大规模实验可能触发 429 错误

**解决**: 添加速率限制

```python
import time

# 限制每分钟 60 次请求
requests_per_minute = 60
sleep_time = 60.0 / requests_per_minute

for agent in agents:
    agent.perform_action()
    time.sleep(sleep_time)  # 等待
```
