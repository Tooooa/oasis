# 集成架构（以当前代码为准）

本文档说明 OASIS 中 Agent 水印（AgentMark）的**实际集成链路与数据流**，内容以仓库当前实现为准。

---

## 架构概览

水印集成的核心思路是：把水印嵌入到“Agent 从多个可用行为中选择一个行为”的过程里，而不是改写平台内容或输出文本。

关键组件：

- **`oasis/social_agent/agent.py`**：Agent 行为决策入口（两阶段：先取概率、再水印采样、再执行）
- **`oasis/watermark/watermark_manager.py`**：水印生命周期管理（bit-stream/ECC/日志/提取）
- **`oasis/watermark/modules/watermark_sampler.py`**：差分水印编码/解码实现（PRG 同步、recombination、cyclic shift）
- **`oasis/watermark/modules/coding_utils.py`**：ECC 编码/解码（`parity` / `hamming` 等）

## 集成策略

### 1) 非侵入式：Agent 可选启用

`SocialAgent` 会尝试导入 `oasis.watermark.WatermarkManager`。如果可用且调用方未显式传入 `watermark_manager`，则会为每个 Agent 自动创建一个独立的 `WatermarkManager`（默认 `mode="full"`，并用 `agent_id` 作为水印 payload）。

对应代码：`oasis/social_agent/agent.py`

### 2) 两阶段决策（Two-phase）

当启用水印时，`SocialAgent.perform_action_by_llm()` 采用两阶段：

1. **阶段 1：获取行为概率分布**  
   调用 `_get_action_probabilities(env_prompt)`，让 LLM 对固定的 `available_actions` 输出 JSON 概率分布。

2. **阶段 2：水印采样**  
   调用 `WatermarkManager.sample_behavior_watermark(probabilities, round_num, context_for_key)`，返回被选中的 action（以及本轮嵌入 bit 数等信息）。

3. **阶段 3：执行行为**  
   按阶段 2 的选择执行对应 action（工具调用），继续进入下一轮。

## 数据流（从嵌入到验证）

### 嵌入阶段（运行时）

1. LLM 输出：`probabilities: Dict[str, float]`
2. `WatermarkManager` 选择 bit-stream（优先级）：
   - 显式 `bit_stream`
   - 否则若提供 `agent_id`：默认用 `format(agent_id, "08b")`
   - 否则用默认 payload `"11001101"`
3. bit-stream 通过 `oasis/watermark/modules/coding_utils.py:encode_payload()` 做 ECC 编码（由 `config["ecc_method"]` 决定）
4. `oasis/watermark/modules/watermark_sampler.py:sample_behavior_differential()`：
   - 对行为名做确定性排序
   - 基于 `context_for_key` 生成 key，并结合 `round_num` 作为 nonce，初始化 PRG（确保编解码同步）
   - 运行差分编码器选出一个行为，并返回本轮嵌入 bit 数
5. `WatermarkManager` 写入日志：每轮以 `Round {round_num}: { ...json... }` 的形式记录

### 提取阶段（离线/回放）

`WatermarkManager.extract_watermark_from_log(log_path)`：

1. 解析日志中每轮的 JSON 记录
2. 对 `bits_embedded > 0` 的轮次，调用 `differential_based_decoder(probabilities, selected_behavior, context_for_key, round_num)` 提取本轮 bit 串
3. 拼接为 `extracted_bit_stream`
4. 按配置调用 `decode_message()` 做 ECC 解码与校验，输出 `decoded_payload`、`valid`、`accuracy` 等统计

## 关键约束（影响正确性）

- **行为集合应固定**：每轮 LLM 估计的概率分布必须对应同一组 `available_actions`。动态增删行为会破坏编解码同步。可参考：`docs/watermark/zh/OASIS行为序列说明.md`
- **`round_num` 必须一致**：PRG nonce 使用轮次编号；提取时必须与嵌入时相同
- **`context_for_key` 必须可复现**：当前实现将其记录进日志，提取时直接使用日志里的 `context_for_key`

## 扩展性设计（当前实现的正确做法）

### 1) 添加/修改 ECC

在 `oasis/watermark/modules/coding_utils.py` 中扩展 `encode_payload()` / `decode_message()` 支持新的 `ecc_method`，并在 `WatermarkManager` 的 `config` 中选择该方法。

### 2) 适配更多平台/动作集

水印模块只要求输入是“行为→概率”的分布。要适配新平台，重点是保证：

- 动作集合可枚举且在模拟期间保持稳定
- LLM 输出的概率字典覆盖同一动作集合
